# 作業記録→日報まとめアプリ 要件定義書（課題2）


## 概要

**システム名（仮）：作業ログ日報**

仕事中に作業ボタンを押すだけで時間を記録し、終業時に「何に何分使ったか」をグラフで集計して、そのまま日報の下書きにするWebアプリ。中心は「記録と集計」で、1個目のメルカリ出品文メーカー（文章生成）とは仕組みもテーマも異なる。

## 背景・課題（誰の・何を・どう解決するか）

- **誰の**：毎日日報を書いている会社員（まずは自分）
- **何を**：終業後に1日の作業を思い出して日報を書く手間。何にどれだけ時間を使ったかも分からない
- **どう解決**：作業の開始・終了をボタンで記録しておき、終業時に自動で集計して日報の下書きにする。思い出す作業と書く作業をなくす

## ターゲットユーザー

- 日報・業務報告の提出が必要な会社員
- 書類確認、メール対応など、細かい作業を1日に何度も切り替えている人
- 自分の時間の使い方を見える化して、効率化したい人

## 機能要件

必須機能（MVP）は「ボタンで記録して、終業時に集計を見る」に絞る。

| 区分 | 機能 | 内容 |
| --- | --- | --- |
| 必須 | 作業ボタン | 「書類確認」「メール対応」「会議」など登録した作業をワンタップで開始。別の作業を押すと前の作業は自動で終了 |
| 必須 | 作業の登録・編集 | ボタンにする作業名を追加・変更・削除できる |
| 必須 | 今日の記録一覧 | 開始・終了時刻と所要時間を一覧表示。押し忘れは手で修正できる |
| 必須 | 集計グラフ | 作業ごとの合計時間を棒グラフ（または円グラフ）で表示 |
| 必須 | 日報の下書き | 集計から「本日の業務（作業名・時間）」を自動で文章化し、コピーできる |
| あれば良い | AIまとめ | 記録とひとことメモから、成果・課題・明日の予定をAIが整える |
| あれば良い | 件数カウント | 「書類確認 ＋1」のように処理件数も記録する |
| あれば良い | 週の振り返り | 1週間分の時間の使い方をグラフで比較 |

## 画面構成と使い方の流れ

2画面だけにする（記録画面と集計画面）。

1. 朝：アプリを開く（作業ボタンは前回の設定のまま）
2. 仕事中：作業を始めるたびにボタンをタップ。今の作業と経過時間が上に表示される
3. 休憩・終業：「停止」ボタンで記録を止める
4. 終業時：集計画面でグラフと記録一覧を確認し、押し忘れがあれば修正
5. 「日報をコピー」で下書きをコピーし、会社の日報に貼る

## 非機能要件（セキュリティ・公開時の注意）

- 記録はブラウザ内（localStorage）だけに保存し、サーバーには送らない。ログイン不要
- 作業名は「書類確認」などの種類だけにし、個人情報や書類の中身は入力しない
- AIまとめを入れる場合、APIキーはVercelの環境変数に保存し、サーバー側（API Route）から呼び出す
- 公開デモ・README・記事のスクショは架空の作業名とデータを使う
- スマホでも押しやすい大きなボタンにする

## 対象外（やらないこと）とスケジュール

**やらないこと**

- ログイン機能、複数端末での同期
- 会社のシステムやSlackとの連携、自動送信
- 書類の中身や個人情報の記録
